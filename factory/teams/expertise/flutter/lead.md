# Keep at most 40 concise, reusable lessons.

- seed: For single-file append tasks, explicitly tell the worker to preserve all existing content unchanged.
- 2026-09-07: Team YAMLs without a `modelProfiles` map only support the `standard` profile — passing `claude light` to `just member-build` when the team YAML has no light-profile mapping makes `delegate.sh` fail with exit code 1; check the team YAML for `modelProfiles` before requesting a non-default profile.
- 2026-09-08: Bash string args passed to `just member-build` go through shell double-quote expansion before reaching the recipe — literal `$var`/`${...}` (e.g. Dart string interpolation like `'$error'` or `'${count}'`) quoted in a task prompt triggers bash "bad substitution"; either escape every `$` as `\$` or describe the code pattern in prose instead of pasting literal interpolation syntax.
- 2026-09-08: When a flutter-engineer member's Bash-dependent verification (flutter analyze/test) is unavailable in its session and it reports being blocked mid-task (e.g. stuck on an unrelated file-edit permission), don't assume the requested code edit failed — check `git diff` on the target file first, since the edit may have already landed before the blocking step; only re-delegate the specific missing piece (e.g. the handoff note) rather than the whole task.
- 2026-09-08: When a cross-model verifier flags "X returns real data instead of the documented fallback on failure", check every catch block in the function individually — a defensive-fallback claim in a doc comment can be true for some failure paths (e.g. GPS fetch) while silently false for others (e.g. reverse-geocoding) if a later catch block was written to only null out one field instead of returning the fallback object.
- 2026-09-08: A cross-model verifier FAIL that names a specific branch (e.g. "isEmpty path returns real data instead of fallback") is often a single missed conditional distinct from a previously-fixed catch block in the same method — verify the exact line range named, fix only that branch, and don't assume the earlier catch-block fix already covers it.
- 2026-09-08: When a `just member-build` prompt contains multi-paragraph text with a mix of code snippets in single-quotes plus contractions/apostrophes, `just`'s own arg parser can fail with a bare "Parse error" even though an earlier structurally-similar multi-paragraph prompt succeeded — the safe fix is to rewrite the prompt avoiding any single-quote-wrapped code identifiers/apostrophe contractions rather than trying to diagnose which exact character broke the parse.
- 2026-09-09: When `SliverAppBar.title` and `FlexibleSpaceBar.title` both render at constant full opacity for `pinned:true, floating:false` app bars (Flutter never fades a pinned title based on scroll), building a collapsed/expanded content swap requires bypassing `FlexibleSpaceBar` entirely — use a `Builder` reading `FlexibleSpaceBarSettings` to compute collapse fraction manually and crossfade with `Opacity`+`IgnorePointer`; do not trust that moving a widget into `FlexibleSpaceBar.title` alone fixes a duplicate-header bug, verify with an opacity-value regression test.
- 2026-09-09: When a custom `SliverAppBar.flexibleSpace` uses a raw `Builder`/`Stack` instead of `FlexibleSpaceBar`, `primary: true` (default) reserves the device status-bar inset in the sliver's extent math but does NOT inset the content itself — wrap the returned widget tree in `SafeArea(bottom: false, ...)` rather than manually adding `MediaQuery.padding.top` offsets; this is a no-op in widget tests (top padding defaults to 0) so no test changes are needed.
- 2026-09-09: A cross-model verifier FAIL that cites a self-doubting code comment (e.g. "X would throw here because no ancestor exists") may be flagging the comment's false claim rather than a real runtime bug — before delegating a behavioral fix, read the actual framework source (e.g. Flutter's `runApp`/`wrapWithDefaultView`/`View.build` wrapping the root widget in `MediaQuery.fromView`) to check whether the claim is even true; if false, fix the comment and add a structural regression test instead of changing working logic. Separately, never trust a prior session's "just check green" note when Bash execution was permission-denied in that harness — always have the lead re-run `just check` directly, since a previously-reported-green file can hide real compile errors (e.g. a stray duplicate closing paren) that no one actually executed against.
- 2026-09-09: When delegating a paren-balance/bracket-count fix via prompt text (no direct Edit access for the lead), don't describe the fix only in prose — give the exact literal old_string/new_string text with precise line content, and always verify with your own `just check` after each attempt rather than trusting the member's self-report, since members repeatedly miscounted the required close count (over-deleted, then under-deleted) across three attempts even with detailed instructions.
- 2026-09-18: When a flutter-engineer member reports it cannot run `flutter analyze`/`flutter test` due to Bash permission scope (only some commands whitelisted for that role), don't re-delegate — the lead should read the diff directly and run `just check` itself to verify, since the lead's own Bash access is broader than the member's sandboxed permissions.
- 2026-09-18: When a cross-model verifier FAIL cites `hasPhoto`/similar boolean computed once from async data and reused across multiple render branches, check whether an `errorBuilder`-style callback that swaps the visual output also updates that boolean — it often doesn't, since the callback only controls what's painted, not the state driving sibling branches; converting the widget to StatefulWidget with the failure tracked via addPostFrameCallback (never setState directly inside a builder callback) is the standard fix.
