# 위를 봐요(Look Up) — 앱 구현 현황

> 2026 관광데이터 활용 공모전 제안서 기반. 새(낮·탐조)와 별(밤·천체관측)을 매개로
> 지역의 낮과 밤을 재발견하는 저탄소 로컬 관광 플랫폼("수직적 여행").
> 핵심 차별성: 기상·천문·조석·빛공해 등 공공 OpenAPI를 융합한 **0~100 적합도 점수 엔진**.
>
> 문서 갱신: 2026-09-21 · 정본 기획: `docs/PRD-look-up.md` · UI 정본: Figma

---

## 0. 제품이 풀려는 문제 / 의미

- **"어디로 갈까"가 아니라 "지금 위를 보면 뭐가 좋은가"** 를 답한다. 같은 장소라도 **낮(하늘의 새)** 과 **밤(하늘의 별)** 은 전혀 다른 경험이며, 그 가치는 날씨·조석·달·빛공해에 따라 시시각각 바뀐다.
- 흩어져 있는 공공 데이터(기상·천문·조석·빛공해·탐방로·조류관측)를 **하나의 0~100 점수**로 융합해, 비전문가도 "오늘 여기, 지금이 좋은 때인지"를 직관적으로 판단하게 한다.
- **저탄소·로컬 지향**: 멀리 가는 관광 대신 가까운 지역의 낮과 밤을 깊게 보는 "수직적 여행". 탐방로(도보)·지역 노포·그린 마일리지로 연결.
- **정직한 데이터 표기 원칙**: 실측(`live`)·근사(`approx`)·불가(`unavailable`)를 화면에서 구분해 보여 준다. 데이터가 빠져도 앱은 저하(`degraded`)만 되고 계속 작동한다.

---

## 1. 기술 스택 / 아키텍처

| 레이어 | 스택 | 역할 |
|---|---|---|
| Backend | FastAPI (Python, uv) | 계약 **publisher**. 공공 OpenAPI 융합·적합도 엔진·CRUD |
| Frontend | Flutter + Riverpod | 계약 **consumer**. iOS/Android 하이브리드 |
| 인증 | Firebase Auth + Kakao 브리지 | Kakao/Google 로그인 + 체험(게스트) 모드 |
| 배포 | Google Cloud Run (asia-northeast3) | 백엔드 실서버, Secret Manager로 키 주입 |

- 앱은 `API_BASE_URL`(dart-define)로 백엔드에 연결. HTTPS.
- 상태관리는 Riverpod. 백엔드 계약은 `apps/backend/.team/member.md`에 publish → flutter가 consume.
- **낮/밤 모드**가 앱 전반의 축: 색·카피·데이터(탐조 vs 천체)가 모드에 따라 바뀐다. (새=골드/낮, 별=틸/밤)

## 2. 화면 구성 (상세)

앱은 **하단 4탭** 셸(`app_shell`) 위에 얹혀 있고, 로그인 게이트(`auth_gate`)를 통과하면 진입한다.

### 진입: 로그인 게이트 (`auth_gate` / `login_screen`)
- **의미**: 로그인은 선택. 게스트도 탐색은 가능하게 해 진입 장벽을 낮춘다.
- Kakao / Google 로그인 + **체험 모드(게스트)** 3갈래.
- 인증 config가 주입되지 않은 빌드에서는 "준비 중" 대신 게스트 탐색으로 부드럽게 폴백.

---

### ① 홈 (`home_discovery_screen`)
**의미**: "오늘, 지금, 여기 위를 볼 가치"를 한 화면에 요약하는 대시보드.

- **낮/밤 모드 토글** — "낮의 새를 찾아서 / 밤의 별을 보러". 모드에 따라 전체 데이터·톤 전환. 자동 모드(시간대 기반)와 수동 전환 배지("자동 모드입니다").
- **지금 시선의 초점** — 현재 모드에서 무엇을 볼지(탐조/천체) 안내.
- **오늘의 통합 관찰 적합도** — 5-레이어 융합 0~100 점수 + 라벨. 데이터 저하 시 정직 표기.
- **골든타임** — 관찰 최적 시간대(낮: 만조 전후 갯벌 유입 피크 / 밤: 달빛 방해 없는 시간창).
- **오늘의 달** — 위상(초승달·상현 반달·보름달·하현 반달·그믐달 등)·조명도·월출/월몰. 천체관측 방해 요소로서의 달빛.
- **야간 전환 별빛 예보** — 일몰·박명 종료 시각과 그 시점 육안 관측 가능한 별자리/방위.
- **당겨서 새로고침**(RefreshIndicator), 상단 헤더는 스크롤 연동(노치 밴드는 고정).

---

### ② 관찰 지도 (`observation_map_screen`)
**의미**: 지역의 관찰 자원을 지도 위에서 레이어로 겹쳐 탐색. "지금 이 근처에 뭐가 있나".

- **지도**: flutter_map(Esri 다크 타일). 4개 **레이어 토글** — 조류 / 별 / 노포 / 탐방로.
- **스팟 마커 + 바텀시트**: 마커 탭 → 하단 시트에서 스팟 상세. 정렬(거리 등)·검색·SQM(밤하늘 밝기) 필터.
- **조류 스팟 개체 산포**(bird scatter): 조류 스팟 확대 시 종별 개체를 지도에 흩뿌려 관측 규모를 시각화.
- **종 상세 스택**: 스팟 → 종 목록 → 종 상세(3단 내비게이션). 종 상세는 위키 요약·보전등급 배지·오늘 조석까지.
- **'이 지역에서 다시 검색'**: 지도를 옮긴 뒤 그 중심 기준으로 재조회.
- **'내 위치'(현재 위치로 이동)**: 앱 시작은 강화도 기준으로 노출하되, 버튼 탭 시 **실제 GPS 위치**로 이동·재조회(권한 요청·미허용 안내 포함). 위치 못 찾으면 "강화 기준으로 표시 중 · 위치 켜기" 배너.

---

### ③ 발견 (`trails_catalog_screen`)
**의미**: 도보로 즐기는 에코 코스 큐레이션 + 코스와 엮인 지역 노포(식당). 저탄소 로컬 소비 연결.

- **거리순 지역 선택기**: 최근접 지역(near_me 강조) + 주변 지역을 거리순 칩으로.
- **대표 탐방로 코스**(두루누비): 코스 카드(거리·소요·난이도), 코스 경유지(RouteStops), 야간하늘 등급.
- **코스 상세 / GPX 경로 지도**(`course_detail` / `trail_route`): 코스 상세와 실제 GPX 경로를 지도로. (홈/카탈로그의 별도 GPX 버튼은 제거, 코스 상세에서 진입)
- **관찰 후 들르는 지역 식당(노포)**: 코스 종점 주변 노포를 거리순으로, 주소·위치 연결.

---

### ④ 낮-밤 패키지 (`packages_catalog_screen`)
**의미**: 낮(탐조)과 밤(천체)을 하나로 묶은 여행 상품 컨셉. 현재는 **시안(예시) 상품** — 일정·가격·혜택 확정 전.

- 카테고리 필터(산림·습지형 등) + 패키지 카드.
- **예약 미리보기**(`package_booking_preview`): 희망 날짜·인원 기준 예시 금액. 실제 결제·상담은 미지원.
- **탄소 배출 절감** 등 친환경 지표(package_extras)로 저탄소 컨셉 강조.
- 이용 안내 시트로 "예시 데이터임"을 명확히 고지.

---

### 보조/공통 화면
- **계정**(`account_screen`) — 로그인/게스트 상태 관리, 게스트는 로그인 유도.
- **디지털 생태 일기**(`diary_list_screen` / `observation_form_screen`) — 관찰 기록 CRUD. 필드: 종 이름·날짜·메모·사진 URL, 낮/밤 구분. "새 관찰 기록 / 관찰 수정".
- **배지**(`badges_screen`) — 관찰 활동 기반 배지(그린 마일리지의 시작점).

## 3. 적합도 점수 엔진 (0~100, 5-레이어)

**의미**: 서로 다른 단위의 공공 데이터를 가중 합산해 "관찰하기 좋은 정도"라는 하나의 숫자로 번역. 앱의 심장.

| 레이어 | 가중치(예) | 데이터 소스 | 의미 |
|---|---|---|---|
| environment(기상) | 0.35 | OpenWeatherMap (→ 기상청 교체 예정) | 시정·구름·강수 — 볼 수 있는가 |
| astronomy(천문) | 0.25 | KASI 출몰시각/천문현상/월령 | 박명·달빛 방해 — 어두운가 |
| lightPollution(빛공해) | 0.30 | VIIRS 위성광 근사 | SQM·Bortle 등급 — 하늘이 깨끗한가 |
| tide(조석) | — | 조석(현재 일부 스텁) | 갯벌 탐조 골든타임 — 새가 모이는가 |

- 각 레이어 상태를 `live` / `approx` / `unavailable`로 **개별 표기**(정직 원칙).
- 낮/밤 모드별로 가중·해석이 달라진다(낮=조석·기상 중심, 밤=천문·빛공해 중심).
- 데이터 도달 불가 시 `degraded:true`로 부분 저하만, 앱은 계속 동작.

## 4. 백엔드 API 엔드포인트

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/health` | 헬스체크 |
| `GET /api/suitability` | 적합도 점수(모드 day/night, 5-레이어) |
| `GET /api/regions` | 지원 지역(거리순 + 최근접) |
| `GET /api/trails` | 두루누비 탐방로 코스 + 야간하늘 + 주변 노포 |
| `GET /api/observation-map` | 지도 스팟(조류/별/노포/탐방로) 집계 |
| `GET /api/species` | 조류 종 상세(위키 요약·보전등급) |
| `GET /api/starlight-forecast` | 야간 전환 별빛 예보(박명·관측 가능 별자리) |
| `GET /api/tide` | 조석 정보 |
| `GET/POST /api/observations` | 디지털 생태 일기 CRUD |
| `GET /api/badges` | 관찰 배지 |
| `POST /api/auth/kakao` | Kakao 로그인 → Firebase custom token 브리지 |

## 5. 데이터 소스 (공공 OpenAPI)

- **data.go.kr 공통 서비스키**: 두루누비(탐방로)·TourAPI 4.0(관광/노포)·관광사진·KASI(천문현상/출몰시각/월령)
- **OpenWeatherMap**: 날씨(임시, 최종은 기상청 단기예보로 교체 예정 — visibility 10km 캡 한계)
- **eBird**: 조류 관측 데이터
- **빛공해**: VIIRS 위성광 근사(키 불필요)
- ⚠️ data.go.kr 계열은 Cloud Run 유동 IP를 차단 → **Cloud NAT 고정 egress IP**로 해결(§7)

## 6. 인증

- **방식**: Firebase Auth. Google 로그인 + Kakao(네이티브 로그인 → 백엔드가 Firebase custom token 서명) + 체험(게스트) 모드.
- **백엔드**: `/api/auth/kakao`가 Kakao 토큰 검증 후 Firebase Admin으로 custom token 발급(서비스계정 키 필요).
- **빌드타임 주입**: `--dart-define-from-file`(gitignore된 config)로 Firebase/Google/Kakao 키 주입. 미주입 시 체험 모드로 폴백.

## 7. 배포 현황 (2026-09-21)

- **프로젝트**: `<GCP_PROJECT_ID>` / **리전**: `asia-northeast3`(서울) / **서비스**: `lookup-backend`
- **URL**: `https://<CLOUD_RUN_SERVICE_URL>` (revision 00003)
- **시크릿**: 공공 API 키 15개 + Firebase Admin 자격증명 → Secret Manager 참조 주입
- **Cloud NAT**: 고정 egress IP `<STATIC_EGRESS_IP>`(Direct VPC egress)로 data.go.kr/KASI 도달 보장
- **비용**: 실질 고정비 ≈ 고정 IP 월 ~$3.65 (GCP는 AWS식 flat NAT 요금 없음)
- **클라이언트 빌드**: iOS 실기기(release) 확인 완료 / Android APK(사이드로드, debug 서명) 산출

## 9. 최근 변경 (2026-09-21)

4. 관찰 지도 **'내 위치' 실제 GPS 이동** — 시작 화면은 강화도 기본, '내 위치' 탭 시에만 실제 위치로 이동·재조회
5. 실서버 Kakao 로그인 활성화(백엔드에 Firebase Admin 자격증명 주입)
