# 트레일·노포 탭: 실데이터와 목데이터 현황

확인일: 2026-09-18. 현재 Flutter 앱 및 로컬 백엔드 구현을 기준으로 정리한다. 이 문서는 트레일·노포 탭의 현황이며 다른 탭 전체에 적용되는 설명은 아니다.

## 화면별 데이터 출처

| 항목 | 구분 | 출처 및 한계 |
| --- | --- | --- |
| 코스명, 시군, 거리, 소요 시간, 난이도, 순환 유형 | 실데이터 | 두루누비 `courseList` 응답을 파싱한다. 실제 걷는 시간이나 현장 난이도를 측정한 값은 아니다. |
| 출발·도착 좌표 | 실데이터 | 두루누비 GPX 파일의 첫 번째·마지막 좌표를 사용한다. 중간 경유지 이름은 제공하지 않는다. |
| GPX 경로 | 실데이터 | 등록된 GPX URL에서 좌표를 읽어 지도에 선을 표시한다. 다운로드·파싱 실패 시 출발·도착 위치만 표시하며 임의의 경로선을 만들지 않는다. |
| 지도 배경 | 실제 지도 | 낮에는 OpenStreetMap, 밤에는 Esri 지도 타일을 사용한다. 대표 카드 미리보기는 출발·도착 위치를 표시하며 GPX 경로선은 별도 지도 화면에서 표시한다. |
| 음식점 이름, 주소, 좌표, 종점과의 거리 | 실데이터 | TourAPI `locationBasedList2`의 음식점 데이터다. 영업 여부, 도보 이동 거리, 노포·백년가게 인증은 검증하지 않는다. |
| SQM, Bortle, 다크스카이 등급 | 임시 생성값 / 목데이터 성격 | 위도·경도를 수식에 넣어 반복 가능한 값을 생성한다. 실제 광해 측정값이나 VIIRS 위성 자료에 기반한 추정이 아니다. `status=approx` 및 `(약)`으로 표시하지만 관측 판단의 근거로 신뢰하면 안 된다. |
| 낮·밤 적합도 점수 및 평가 문구 | 실데이터와 임시값을 섞은 앱 계산값 | 기상·천문·조위 제공자의 점수와 임시 광해 점수를 가중 합산한다. 공공기관이 제공하는 공식 적합도 점수가 아니다. 일부 제공자는 실패 시 사용할 수 없는 상태 또는 고정 대체값을 반환한다. |
| 헤더, 소개 문구, Day-to-Night 배지 | 고정 UI 문구 | 동적 관측 결과나 인증 데이터가 아니다. |
| 코스 주요 지점 | 실좌표에 고정 설명을 붙인 UI | GPX 출발·도착 좌표를 표시한다. ‘도착 · 밤하늘 관측 지점’이라는 문구는 현장 관측 시설·안전·접근 가능 여부를 확인했다는 뜻이 아니다. |

앱의 기본 연결은 `HttpTrailsApi`와 `HttpGpxApi`다. `FakeTrailsApi`·`FakeGpxApi`는 테스트 및 일시적인 렌더링 검토용이며, 이번 시뮬레이터 실행에서는 사용하지 않았다. 시뮬레이터는 `API_BASE_URL=http://127.0.0.1:8000`으로 로컬 백엔드에 연결했다.

## 코스 및 위치 검색 기준

- Flutter는 현재 위치의 위도·경도를 `/api/trails`에 전달한다.
- 그러나 백엔드는 전달받은 위치로 권역을 결정하지 않는다. `DEFAULT_REGION_LABEL="인천 강화군"`, `DEFAULT_REGION_TOKENS=["강화"]`로 고정되어 있다.
- 따라서 사용자가 실제 위치를 이동하거나 관찰 지도를 다른 지역으로 옮겨도 트레일 검색 권역은 바뀌지 않는다. 지도 중심 이동을 기준으로 트레일을 재검색하는 연결도 없다.
- 현재 ‘전체 권역’은 이번 응답에 포함된 코스 전체를 뜻한다. 전국의 모든 권역을 검색하는 기능이 아니다.
- ‘이 권역의 다른 코스’는 같은 강화군 응답의 나머지 실제 코스다. 모든 코스의 전체 목록은 아니다.
- 백엔드는 가져온 코스에서 강화군을 골라 코스 ID 순으로 최대 15개 후보를 선정한다. GPX 종점·광해 정보를 얻은 후보를 임시 SQM 값이 큰 순으로 정렬하고 최대 5개를 반환한다.
- 낮·밤 적합도는 응답의 첫 번째 코스에만 계산한다. 다른 코스의 적합도 정보가 없는 것은 목데이터로 채운 상태가 아니라 현재 계산 범위의 제한이다.

## 음식점 검색 기준

1. 각 코스의 GPX 마지막 좌표, 즉 **각 코스의 종점**을 기준으로 검색한다.
2. TourAPI에 종점 좌표, 반경 5,000m, 음식점 분류(`contentTypeId=39`), 거리순(`arrange=E`)을 전달한다.
3. 최대 10개 응답을 요청하고, 반환된 거리로 정렬해 가까운 3곳을 각 코스에 붙인다.
4. 화면의 주변 음식점 목록은 선택된 권역의 코스별 결과를 합치고 콘텐츠 ID 기준으로 중복을 제거한다. 동일 음식점이 여러 코스에 있으면 종점과의 거리가 가장 짧은 코스의 정보와 지도 연결을 유지한다.

따라서 **음식점 검색은 종점 기준이 맞다.** 다만 화면에 합쳐진 모든 음식점이 대표 코스 하나의 종점 기준인 것은 아니다. 표시된 ‘종점에서 ○m’는 연결된 코스의 종점 기준 API 거리이며 실제 도보 경로 길이나 도보 시간을 계산한 값은 아니다.

## 오해를 줄 수 있는 현재 표시

- **‘밤하늘이 가장 어두운 순서예요’**: 임시 생성 SQM 값으로 정렬한다. 실제 광해 자료가 연결되기 전에는 검증된 추천 순위라고 설명하면 안 된다.
- **적합도의 ‘실시간’**: 백엔드는 `degraded=false`이면 이 표시를 반환한다. 점수 합산에서 `approx` 및 `stub`는 사용 가능한 값으로 취급하므로 모든 입력이 실시간 관측값이라는 뜻이 아니다. 임시 광해 점수 비중은 낮 15%, 밤 30%다.
- **‘지역 노포’**: 실제 주변 음식점이지만, 오래된 가게인지 또는 백년가게 인증이 있는지는 확인하지 않았다. 현재 데이터에 맞는 표현은 ‘주변 음식점’이다.
- **‘도착 · 밤하늘 관측 지점’**: 종점 좌표만 확인된 상태다. 지정 관측 장소나 시설이 확인된 것은 아니다.

위 항목은 문서로 명시한 기존 제한이다. 이번 문서 정리에서 UI 문구나 백엔드 계산 로직을 추가 수정하지 않았다.

## 시안에서 아직 구현하지 않은 항목

- 누적 도보 거리·포인트 적립·탄소 감축 실적
- 제휴 인증·할인·에코 스테이·숙소 정보
- 코스별 조류 개체 수·관측 피크 시간·실시간 현장 리포트
- GPX 파일 저장 및 오프라인 지도 다운로드: 현재 버튼은 **GPX 코스 지도 보기**다.

이 항목들은 API 데이터가 없거나 기능이 연결되지 않아 임의의 숫자·가게·혜택으로 채우지 않았다.

## 검증 및 다음 작업

`just flutter-check`로 정적 분석과 전체 테스트 175개를 통과했고, 낮·밤 레이아웃 및 320px 화면의 큰 글씨를 확인했다. iPhone 17 Pro 시뮬레이터 빌드·실행과 로컬 백엔드의 실제 코스·음식점 응답 표시도 확인했다. 테스트에서 GPX 성공·누락·재시도를 확인했지만, 시뮬레이터에서 실제 GPX URL을 열어 경로를 확인한 것은 아니다.

다음 개발 후보는 현재 위치·지도 중심 기반 코스 검색, 실제 광해 자료 연결, 적합도 출처 표시 보완, ‘노포’ 및 관측 지점 표현 수정이다. 아직 완료된 기능이 아니다.
